# SchoolHeat App Operation Manual

This manual explains how to use the published SchoolHeat web app. It is written
for teachers, students, and project staff who record heat readings, sync the
ESP32 sensor, and manage heat alerts. It does not cover firmware changes or
cloud administration.

## 1. Before you start

- Open the published **HTTPS** SchoolHeat site. Bluetooth sync, Firebase,
  phone push, App Check, and SMS require a secure context.
- Open the app online once on each device, then use the browser's **Install
  app** or **Add to Home Screen** option. The app shell is cached for offline
  startup.
- Readings and settings are saved in **that browser only**. Offline changes do
  not automatically sync between devices.
- Internet is required for **Firebase sync, phone push, App Check, and SMS**.
  Sensor readings can be imported with the local bridge or Bluetooth while
  offline.
- There is no username/password screen in the app. Firebase sign-in is
  automatic and anonymous. The only password involved in normal operation is
  the private ESP32 Wi-Fi password configured in firmware.

## 2. App tour

The top bar shows the SchoolHeat name, the live date/clock, an **AUTO** badge
while Wi-Fi auto-read is running, and a freshness chip that starts at
**NO DATA** and later shows **RECENT** or **STALE**.

| Tab | What it is for |
| --- | --- |
| **Overview** | Latest saved reading, heat guidance, quick links, and status previews. |
| **Sensor Monitor** | Enter readings manually, sync the ESP32, and check Sensor Trust. |
| **Campus Map** | View the 29 mapped campus pins and tap a pin for its status. |
| **History & Analytics** | Search, filter, chart, export, and delete saved readings. |
| **Forecast** | 60-minute outlook generated by a scheduled Python job and published as `forecast.json`. |
| **Settings** | Language, theme, install, alert controls, calibration, and data tools. |
| **Emergency Hotlines** | Emergency call guidance and verified/awaiting-verification numbers. |
| **About** | Purpose, DepEd 4H bands, workflow, FAQ, and Ask SchoolHeat. |

Keyboard shortcuts: press `1`–`8` to switch tabs, `N` to open Monitor and focus
the location field, `C` to calculate, and `D` to start/stop auto-read. Press
`Enter` in a temperature or humidity field to save the reading.

## 3. Record a reading

### 3.1 Choose a location

1. Go to **Sensor Monitor**.
2. Click **Choose on map**. The app opens the campus map; tap a pin to set the
   sensor location and return here. All 29 mapped campus sites are pinned.
3. For **Einstein Classroom**, **Newton Classroom**, and **Locke Classroom**,
   use the **Location** list under **Study classrooms**. You can also tap one
   of the **Recent:** chips for your last five locations.

### 3.2 Enter a manual reading

1. Enter **Temperature (°C)**, for example `32.5`.
2. Enter **Humidity (%)**, for example `75`.
3. Watch **Live Preview** update the heat index and status.
4. Click **Calculate & Save**.

Temperature must be 0–60 and humidity 0–100. If a field is missing or out of
range, the app shows a validation message instead of saving. After a successful
save, the dashboard, history, map, and gauge refresh and a toast confirms the
result.

The DepEd 4H bands used by the app are:

| Status | Heat index |
| --- | --- |
| **Hayo** | below 27 °C |
| **Hinay** | 27–32 °C |
| **Hinga** | 33–41 °C |
| **Hinto** | 42 °C or higher |

### 3.3 Understand freshness

The latest saved reading is marked **RECENT** for up to 15 minutes, then
**STALE**. Freshness is based on the reading timestamp. It does **not** prove
that a sensor is connected or calibrated. A **DEMO DATA** marker means the
reading was generated by the app for preview and is excluded from forecasts.

## 4. Sync readings from the ESP32

The ESP32 samples every five minutes measured from power-on, not from clock
sync. Syncing the clock does not reset that interval. Each board keeps readings
separate by its chip ID, so set a unique `DEVICE_NAME` on every board.

### 4.1 Wi-Fi auto-read (bridge required)

1. Power the assigned ESP32 and join the laptop to its configured Wi-Fi name.
   A “No internet” warning is expected.
2. Keep `start-local-bridge.ps1` running in an open PowerShell window on that
   laptop. The bridge binds to localhost and accepts only this project's
   GitHub Pages origin.
3. In **Sensor Monitor**, choose the sensor location on the map or from the **Location** list.
4. Click **Auto-Read ESP32 (Wi-Fi)**. The button changes to **Stop ESP32
   Auto-Read (Wi-Fi)** and the header shows **AUTO**.
5. The app polls the bridge, sets the clock on first run, requests one
   immediate sample, and imports new saved readings every 20 seconds.
6. Click **Stop ESP32 Auto-Read (Wi-Fi)** when finished. The ESP32 continues
   logging while powered.

### 4.2 Bluetooth sync (no bridge)

1. Use the HTTPS app in desktop Edge or Chrome with Web Bluetooth support.
2. In **Sensor Monitor**, choose the location on the map or from the **Location** list first.
3. Click **Sync via Bluetooth** and choose the assigned device name in the
   browser permission prompt.
4. Keep the laptop within Bluetooth range until the sync finishes. The app
   sets the clock/location when needed and imports saved records, skipping
   duplicates already in this browser.
5. Bluetooth sync transfers stored data only; it does **not** trigger a new
   sample. Bluetooth is not password-protected, so use it only in a trusted
   environment.

## 5. Alerts

Alerts are only generated for **new or changed Hinga/Hinto** levels from a
recent, valid, non-demo reading. Repeating the same level does not resend.
The alert activity list records risk readings, **not proof of delivery**.

### 5.1 Browser notifications

1. Go to **Settings** and enable **Browser Notifications**.
2. Allow notification permission when the browser asks.
3. Use **Test Browser Notification** to confirm it works.

### 5.2 Phone push alerts

1. Enable **Phone Push Alerts** in **Settings** and allow notifications.
2. Enable it on the laptop running SchoolHeat and on every receiving phone.
3. Internet, HTTPS, the service worker, Firebase Anonymous Auth/App Check, and
   the deployed Cloud Functions are required.
4. Use **Send Test Phone Push** to verify delivery. Phone push does not use SMS
   credits, but phones need internet. The server allows one push request every
   five minutes project-wide.

### 5.3 SMS alerts

1. In **Settings → Alert Notifications**, enter 1–5 Philippine mobile numbers
   in **SMS recipient numbers**, separated by commas, semicolons, or new lines.
   Accepted forms include `09XXXXXXXXX` and `+639XXXXXXXXX`.
2. Only add numbers whose owners consent. Numbers stay in this browser.
3. Enable **SMS Alerts**. It is off by default.
4. **Send Test SMS (may queue and use credits)** sends:
   `SchoolHeat test alert: SMS setup is working.`
5. Each attempt is first written to a local queue, then sent through the
   configured SMS Worker with Firebase and App Check tokens. The Worker allows
   **one SMS request every five minutes per account, including test messages**.
6. If the device is offline, the message stays queued. The app retries on
   reconnect and after retry delays. The queue holds up to **20** messages.
7. **Retry Queued SMS** resumes queued messages. **Cancel Queued SMS** clears
   them but keeps recipients and settings. An in-flight send cannot be
   cancelled.
8. SMS requires an active provider, credits, and an approved sender set by the
   administrator. If a send is unclear, check the provider's message log before
   trying again; the app does not automatically resend unclear failures.

Use the test SMS only when verifying a new setup. It counts toward the
five-minute limit and may use one credit.

## 6. History, forecast, and map

### History & Analytics

- Search by location or status and filter by **All Status / Hayo / Hinay /
  Hinga / Hinto**.
- The **Heat Index Trend** supports tap, drag, and arrow keys. **Show Status
  Summary** gives a breakdown.
- **All Readings** shows 50 per page. Use the trash button to delete one
  reading from this browser; this cannot be undone. The published Python
  forecast uses the separate CSV dataset and is not changed.
- **Choose data file** now does both jobs: it imports a CSV or XLSX into this
  browser's `sh_readings`, converts the valid imported rows to the six-column
  forecast CSV, and sends that CSV to the upload Worker. Enter the forecast
  access code once and leave **Remember code on this device** checked; later
  files update History and the published forecast automatically. Firebase
  sign-in, App Check, and one upload per account every five minutes are
  required. The GitHub token is stored only on the upload Worker. Demo
  readings are never uploaded.
- **Export CSV** includes a **Demo Data** column. **Export JSON** saves
  `schoolheat_readings.json`.

### Forecast

The **60-Minute Forecast** is generated by a scheduled Python job from
`data/schoolheat_readings.csv`, not from this browser's saved readings. The
source series label comes from `data/schoolheat_forecast_source.json`; it is not
a campus map pin. It compares Random Forest, XGBoost, and LightGBM on
non-overlapping 60-minute holdouts, ranks RMSE and MAPE with equal weight, and
selects the lowest combined rank. The comparison panel shows RMSE and MAPE.
Until the job publishes `forecast.json`, the app says the forecast has not been
generated. Sensor calibration is not verified by the forecast.

### Campus Map

The map shows 29 fixed campus pins with zoom controls **-**, **+**, and
**Reset**. Tap a pin for its status. The mapped-pin coverage figure counts
saved location names that match pins; it can include demo or stale data and is
not a live sensor-coverage measure.

## 7. Settings and preferences

- **Install & Offline Use**: shows install status and the **Install
  SchoolHeat** button.
- **Color System**: choose a palette, swatch, harmony style, or full color
  picker. **Reset to SchoolHeat** restores defaults. Heat-risk colors never
  change.
- **Text size**: drag the slider or enter any value from 50% to 250%. The choice
  is saved in this browser and also applies when you open the manual reader.
- **App language**: English, Tagalog, Bisaya, or Waray. Navigation, common
  labels, some safety guidance, and About are translated. Sensor/location names
  and some technical messages stay in English. Risk labels remain
  Hayo/Hinay/Hinga/Hinto.
- **Sensor Calibration**: **Temperature Offset** and **Humidity Offset** adjust
  future calculations.
- **Demo Mode / Generate Demo Data**: creates sample readings for preview.
  Demo readings are excluded from forecasts.
- **Clear All Data**: deletes all readings in this browser. This cannot be
  undone.
- **Firebase Sync, Outlier Detection, Spike Detection**: these toggles are
  saved as preferences; they do not change current alert behavior.

## 8. Hotlines and About

**Emergency Hotlines** shows **911 / TAP TO CALL** and call-prep prompts:
**Where are you?**, **What happened?**, **Stay available.** You can also add
local contacts by saving only a role and phone number. Contacts stay in this
browser, can be edited or deleted, and the **Call** button opens the device
dialer. SchoolHeat does not verify these contacts, sync them, or send them
alerts, and no Mahaplag-specific numbers are hardcoded. This page is not an
emergency dispatch or medical service, and SMS alerts do not contact
responders.

**About** explains the purpose, DepEd 4H bands, workflow, and data limits.
**Ask SchoolHeat** answers a fixed set of questions locally from saved non-demo
records and documented behavior. It does not send questions or readings to an
AI service.

## 9. Important limits and safety notes

- ESP32 readings are local to the browser that imports them.
- A **RECENT** label is not proof of connection or calibration.
- Alerts are advisory. Follow school policy and local advisories.
- The ESP32 has no real-time clock. A reboot without a connected app can
  produce untimestamped records.
- The ESP32 flash log rotates out its oldest records when full.
- Offline mode does not provide internet services.
- Clearing site data deletes queued SMS and local readings.
- Do not change published firmware as part of normal app operation.

## 10. Troubleshooting

| Symptom | What to check |
| --- | --- |
| No readings after auto-read | ESP32 powered, correct Wi-Fi, bridge running, location selected, browser origin allowed by the bridge. |
| Latest reading shows **STALE** | The timestamp is older than 15 minutes. Sync again or enter a new reading. |
| Forecast unavailable | Check that `forecast.json` is published and the scheduled Python job has completed. |
| SMS not arriving | SMS Alerts enabled, recipient valid, internet available, provider credits and approved sender active, queue not cancelled. |
| Test SMS rate-limited | Only one SMS request per five minutes per account; wait and retry manually. |
| Phone push not arriving | Push enabled on sender and receiver, notification permission granted, internet available, Cloud Functions deployed. |
| Map pin shows no saved reading | No saved reading matches that mapped location name yet. |
| App opens but services fail | Confirm the HTTPS site was opened online once and that App Check/Firebase configuration is valid. |
